# Completion Checklist

Use this reference before finalizing a complex TGL-Rec task.

## Local Work

- Check `git status --short` before summarizing.
- Verify that edits are scoped to the requested task.
- Do not revert unrelated user changes.
- Run targeted tests or smoke commands. If tests cannot run, state why.
- Update durable docs only when direction, commands, baseline status, server outcomes, or reportability gates changed.
- Commit and push completed local work unless the user asked not to or a blocker prevents it.

## Research Integrity

- State whether any result is real, diagnostic only, blocked, or not yet run.
- Do not infer server success without pasted logs.
- Do not claim paper readiness before the Phase 10 ending gate passes.
- Keep protocol, candidate, split, event ID, and evaluator comparability explicit.

## Final Response Shape

For complex tasks, include:

- what changed;
- what was tested;
- whether the task is complete or blocked;
- the next concrete plan;
- the current gate toward ending experiments and starting writing.

Keep the report concise and high signal.
